# R3 机型适配与真机验证

## 适配原则

- 所有机型走同一套 CameraX 实现，不在代码中为每个型号复制逻辑。
- 启动时读取当前设备支持的相机、分辨率和帧率范围，选择最接近目标能力的配置。
- 算法统一使用旋转、镜像和设备角色元数据；前摄画面不在 R3 层做像素镜像。
- 优先使用个人基线消除相机位置和用户差异，不硬编码机型镜头参数。
- 无相机、无权限或运行异常时降级到 `NoCameraStreamer`，番茄钟、提醒和报告继续可用。

## 支持等级

| 等级 | 承诺 | 判定方式 |
| --- | --- | --- |
| A 完整验证 | 真实相机取流、校准和拦截通过任务卡全部量化指标 | 本文机型矩阵有完整实测记录 |
| B 通用可用 | CameraX 启动成功，自动选择分辨率和帧率，功能可运行 | 模拟器或至少一次真机冒烟测试 |
| C 安全降级 | 无法取流时不崩溃，无相机功能仍可用 | 无相机/拒绝权限自动化或手工验证 |

未列入机型矩阵的 OPPO 机型只能声称“使用统一 CameraX 路径并支持安全降级”，不能声称已经达到同等帧率、温升或识别效果。

## 测试步骤

1. 在目标 OPPO 手机上安装 Debug APK，并授予相机权限。
2. 进入 P03，确认前摄可用、画面方向和比例正常；无前摄时记录自动回落后摄。
3. 连续采集 30 分钟，记录实际输出帧率、CPU、内存、温升和电量变化。
4. 分别遮挡人脸、制造低光/反光、移动手机，确认校准暂停并能在恢复后继续。
5. 完成一次正常校准，记录选中的分辨率、帧率范围和有效帧数。
6. 将截图、日志、设备型号和系统版本附到 PR 或测试记录中。

## 当前结论

截至 2026-11-21，统一 CameraX 取流和校准状态机已经实现并通过 JVM 单元测试；当前没有目标 OPPO 真机，因此 8fps/30min、温升、耗电和真实相机异常场景均为“待验证”。
