# 算法选型结论（X00 · R4）

> 状态：**R4 侧已定**。协议 v0（`docs/接口协议v0.md`）从草案转正式需 R1+R4 在 PR 中双方确认。

## 结论：MediaPipe Tasks Vision（FaceLandmarker），禁止自训模型

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| **MediaPipe Tasks Vision（FaceLandmarker）** | ✅ 采用 | 端侧离线、免费、Apache-2.0；478 人脸关键点 + facialTransformationMatrix（3D 头位）+ blendshape（eyeBlinkLeft/Right、jawOpen 等可直接映射协议字段）；CPU/GPU 可选；官方 Android 接入即 `com.google.mediapipe:tasks-vision` |
| ML Kit Face Detection | ❌ | 只出轮廓 4 点位姿，无眼部/嘴部关键点，T2-06 眨眼、T2-08 困倦做不了 |
| 自训模型（YOLO 关键点等） | ❌ 禁止 | X00 卡点明确禁止自训人脸关键点；无标注数据、无训练周期 |
| MediaPipe Pose | 备选增强 | 只在「离座判定（是否有人）」需要时叠加，不做主通道 |

## 字段映射（协议 v0 ← FaceLandmarker 输出）

| 协议字段 | 来源 |
| --- | --- |
| facePresent / conf | FaceLandmarker 检测结果与 confidence |
| faceScale | 双眼外眦距离 / 图像宽度（归一化，与基线同口径） |
| headPitchDeg / headYawDeg / headForwardDeg | facialTransformationMatrix 分解欧拉角 |
| shoulderTiltDeg | 画面内双肩连线倾角（Pose 或肩部关键点，前视模式由 FaceLandmarker 近似） |
| eyeOpenRatio | blendshape eyeBlinkLeft/Right 均值的补（1-blink） |
| mouthOpenRatio | blendshape jawOpen |
| blinkRatePerMin | `algo/BlinkCounter` 对 eyeOpenRatio 波形计数 |
| lumFace / lumDesktop / lumBackground | 三区灰度统计 |
| overexposureRatio / leftRightDelta | 直方图统计 |

## 判定层（本仓库已实现，`vision/algo/`）

- T1-04 `BaselineCalculator`（中位数基线，重建偏差 <5%）
- T2-01 `DistanceMonitor`（三档 + 滞回 + 剂量累计）
- T2-02 `PostureDetector`（多帧确认，事件起止误差 ≤1s）
- T2-03 `SittingMonitor`（久坐/离座/恢复）
- T2-04 `LightClassifier`（六类光照，不出 lux）
- T2-05 `OffScreenTracker`（离屏占比 + 抬头/转头次数）
- T2-06 `BlinkCounter`（眨眼率 + 长时间不眨眼）
- T2-08 `DrowsinessDetector`（4 类特征，可降级为 3 类）
- T2-09 `DrowsinessGrader`（轻/中/重，规则可解释）
- T2-10 `FusionStateMachine`（六态融合，滞回 + 最短保持，1s 内不反复跳变）

全部为纯 Kotlin（无 Android 依赖），单元测试锚定任务卡量化指标；
「与人工标注一致率 ≥85% / 召回 ≥80%」类验收待 X08 标注数据到位后回归。

## 真引擎接入路径（后续 PR）

1. 加依赖 `com.google.mediapipe:tasks-vision`，实现 `vision/MediaPipeVisionEngine : VisionEngine`
   （订阅 `CameraStreamer.frames()` → FaceLandmarker → 特征 → `algo/` 判定层 → `VisionSample`）；
2. 单帧分析 ≤120ms（8fps 预算）；模型加载失败抛异常不静默；
3. 只改 `AppContainer.visionEngine` 一行绑定，UI/报告零改动。
