# 视觉接口协议 v0（R4 · X00 交付物）

> 状态：**正式 v0（2026-11-22 定稿）**。协议变更由 R4 定稿（R1 已豁免双签，见 AGENTS.md 硬规则 6），走正常 PR 流程。
> 落点：代码侧数据类 `vision/protocol/VisionModels.kt`（`VisionSample` / `FusionState`）。
> 进程内传对象（Flow），**JSON 仅用于落盘对齐与复赛文档**，不做跨进程序列化。

## 0. R3 → R4 相机帧输入 `CameraFrame`（R3 已实现，待 R4 确认）

现有 `VisionEngine.samples()` 只描述 R4 的输出，不负责把相机画面传给 R4。
R3 新增 `CameraStreamer.frames(): Flow<CameraFrame>` 作为相机帧入口；R4 的视觉引擎订阅此流，
继续作为唯一 `VisionSample` 生产者。`VisionSample` 字段不变。

代码位置：`vision/CameraStreamer.kt`

| 字段 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `tsMs` | `long` | R3 收到帧时的单调时钟时间 | 使用 `MonotonicClock`，禁止墙钟 |
| `seq` | `long` | R3 递增帧号 | 可用于检测丢帧 |
| `width` / `height` | `int` | YUV 原图尺寸 | 由当前 OPPO 机型实际协商结果决定 |
| `rotationDegrees` | `int` | CameraX 给出的顺时针旋转角 | R4 在进入模型前统一坐标 |
| `isFrontFacing` | `bool` | 是否使用前摄 | 帧像素不做镜像；是否水平翻转由 R4 统一处理 |
| `isDeviceMoving` | `bool` | 手机是否正在移动 | R3 使用陀螺仪优先、加速度计兜底；保留 500ms |
| `nv21` | `byte[]` | 已去除行填充的紧凑 NV21 | CameraX 的 ImageProxy 已复制并关闭，R4 可安全异步使用 |

取流约束：

- `STRATEGY_KEEP_ONLY_LATEST`，处理不及时只丢旧帧，不排队；
- 默认目标 8fps，校准采集目标 15fps；
- 优先前摄，无前摄时自动后摄；
- 分辨率请求 640×480，由 CameraX 在运行时选择设备最接近的受支持档位；
- 无相机或无权限时切换 `NoCameraStreamer`，其余产品链路不崩溃。

## 1. 样本流 `VisionSample`（每秒 2~8 条，与取流帧率匹配）

| 字段 | 类型 | 含义 | 约束 |

| seq | long | 递增帧号 | 断流判定依据 |
| facePresent | bool | 是否检测到人脸 | |

| headPitchDeg / headYawDeg / headForwardDeg | float | 俯仰（正=低头）/偏航/前倾 | 正面模式前倾无意义 |

| eyeOpenRatio / blinkRatePerMin / mouthOpenRatio | float | 眼口指标 | T2-06/T2-08 输入 |

| lightClass | string | normal/dark/backlight/glare/uneven/night | 不出 lux 值 |

## 2. 六态融合 `FusionState`

`NORMAL / NEAR / HEAD_DOWN / DROWSY / OFF_SCREEN / AWAY`

- 滞回与最短保持时间在**算法端**做（验收：1s 内不反复跳变）；
- 客户端只在 `StateStreamDebouncer` 加 800ms 确认窗（防 UI 抖动）+ 3s 断流兜底（X18）。

## 3. 风险事件（提醒引擎输入，T2-02/T2-03/T2-09 产出）

`RiskEvent(type, level, startMs, durationMs)`

- type：DISTANCE / POSTURE / DROWSINESS / LIGHT / SEDENTARY / OFF_SCREEN；
- level：LIGHT / MODERATE / SEVERE；
- 事件**起止误差 ≤1s**（T2-02 验收）；多帧确认在算法端完成，客户端不再做阈值判断；
- SEVERE 事件会触发健康优先番茄提前休息（T3-01）。

## 4. 基线（T1-04）

校准 5–10s 的帧数据 → `PersonalBaseline`（字段与 `BaselineEntity` 一一对应）：
脸尺度、俯仰、偏航、前倾、肩线、人脸/背景亮度、置信度、样本数、场景标签。
验收：字段完整率 100%，重建偏差 <5%。

## 5. 断流与降级

- 客户端 3s 无有效样本（conf≥0.5）→ UI 提示「检测中断」，保留最后状态（X18 已实现）；
- 无相机/无权限 → `NoCameraStreamer` 降级，提醒与报告链路照常（X14 兼容矩阵承诺）；
- 算法首版（D3 晚）只需实现 `VisionEngine` 接口 + 到 `AppContainer` 改一行绑定。

## 6. 性能约束（给 R4 的硬指标）

- 单帧分析 ≤120ms（8fps 预算）；样本产出频率 ≥2Hz、≤8Hz；
- 全部计算在端侧，禁止联网；模型加载失败必须抛出明确异常而不是静默黑屏。
